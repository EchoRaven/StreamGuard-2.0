# 15 · 相关工作与定位（2026-09 核实）

⚠️ **结论先说:级联架构本身已经不新了。** 2026 年 5 月的 SafeLens 做了
几乎相同的事,而且用的是同一套数据和同一个基座。必须调整定位。

✅ **但定位不是退让。** 从 SafeLens 自报的运行时可反推出它升级率 34.3%
(§3.4.1),这在任何流式截止期下都不可行 —— 流式不是"同一问题的在线版",
是三条约束同时收紧的**另一个问题**(§3.4)。

## 1. 最直接的竞争:SafeLens（arXiv 2605.17610）

### 1.1 它具体怎么做的

> ⚠️ **本节早先版本有两处事实错误,已按 Algorithm 2 原文更正**:
> (a) 曾写"S1 = 探针 + Florence-2 逐帧 caption" —— 错,caption **只在 S2
> 分支**生成(第 10 行),S1 就是探针本身,这才是 0.04s 的来源;
> (b) 曾把 "Rolling" 当成纯命名 —— 错,它**确实是滑动窗口**,而且是因果的。
> 更正 (b) 让结论**更有利**,见 §1.3。

**S1 — 只有探针,没有 caption。** 一个探针 `P_φ: R^(n×d) -> Δ^p`,
直接读**微调后的 Qwen3-VL-2B 的最终层隐状态**;置信度取 max 概率 `q̂`,
`q̂ ≥ τ`(默认 0.9)直接出判决,否则升级。**0.04s 里只有这一次探针前向。**

**S2 — 同一个模型,换推理模式。** 升级后才生成 caption,再拼进 prompt:
`X̃ = [X; c; q]`,让**同一个微调过的 2B** 做结构化 CoT。
所以它的级联不是"小模型 → 大模型",是"探针读隐层 → 同模型生成推理链"。

**推理路径(Algorithm 2 逐行)**:

```
3:  从 v 采 T 帧，≤1fps
4:  H ← M_θ^CoT 在 (v, X) 上的最终层隐状态        ← 第一次全视频前向
5:  q ← P_φ(H)
6:  ŷ^S1 ← argmax_k q_k
7:  if ŷ^S1 ≥ τ:  直接返回                        ← 0.04s 路径
10:     c ← {C(f_t)}_{t=1..T}                      ← T 次 Florence-2
11:     X̃ ← [X; c; q]
12:     Y^CoT ← M_θ^CoT(v, X̃)                     ← 第二次全视频前向 + 生成
```

升级一次要付:**全视频前向 x2 + T 次 caption + 一次 CoT 生成**。
这就是 5.02s 的构成,而且**它随视频长度增长**(30s/60s/120s 视频
@1fps 分别是 30/60/120 次 caption 调用)。
**流式下视频没有长度 —— 这个量根本不收敛。**

### 1.2 训练管线:三步串行,骨干冻结训探针

```
① TracIn 影响筛选   SafeWatch 2M ──筛──> 48K (2.4%)
                    I(i,j) = ∇_θ ℓ(v_i,X_i,Y_i;θ) · ∇_θ ℓ(v_j,X_j,Y_j;θ)
                    剔除:对同类验证集平均影响 ≤ 0,或对全验证集 < 0
② 微调 VLM          M_θ ──在 48K 上微调──> M_θ^CoT  (CoT 由 Qwen3.5-27B 生成)
③ 冻结,单独训探针   H ← M_θ^CoT 的最终层隐状态
                    D_probe = {(H_i, y_i)}  ──> 训 P_φ,骨干不动
```

**探针是微调之后单独训的,不是联合训练。** 由此得到本文最值得学的一点:

> **一次微调同时产出两级。** S1 不是另一个模型,是 S2 那个模型的
> 隐状态上挂的一个探针。

探针有多小:query 向量 `q ∈ R^d` 加一个线性头。d=2048、7 类时约
**1.6 万参数(占 2B 的 0.0008%)** —— 训练成本可忽略,
**全部成本都在那次 VLM 微调上**。他们的级联几乎没有额外训练代价。

⚠️ 但**他们一个训练超参都没公布**:优化器、学习率、epoch、batch、
LoRA 还是全参,Appendix M 里也没有实质内容。复现其数字要自己定这些。

### 1.3 ★ rolling max 本身就是流式统计量 —— 这是个礼物

"Rolling Attention Probe" 出自 Gemini probes(Kramár et al., 2601.11516):

```
v̄_t = Σ_{j=t-w+1}^{t} α_j v_j / Σ_{j=t-w+1}^{t} α_j       (默认 w=10)
输出 = max_t v̄_t
```

它解决的是**长上下文下的信号稀释**:标准 attention probe 在长序列上会把
有害信号摊平,限制在局部窗口内聚合就不会。

**关键**:`v̄_t` 只依赖 `t-w+1 … t` —— **它是因果的**;
`max_t v̄_t` 是一个**在线可算的 running maximum**。

> **所以正确的说法不是"他们的探针不能流式",而是
> "他们用了一个流式统计量,却丢掉了它的流式性,也没有延迟保证"。**
> 这比断言"不可迁移"更准确,也更有力 —— 它能被他们自己的架构验证。

与我们的 CUSUM 是同一类东西的两个版本:

| | rolling probe | 我们的 CUSUM |
| --- | --- | --- |
| 统计量 | `max_t v̄_t`,窗宽 w 固定 | `S_t = max(0, S_{t-1}+z_t−k)` |
| 记忆 | 硬截断在 w 步 | 指数式,自适应 |
| 阈值 | 验证集上最小化加权错误 | conformal 下界 |
| 变点后重置 | 无 | 有 |
| 延迟保证 | **无** | `E[(τ−ν)⁺]` |

⚠️ 另:SafeLens 探针读**最终层**,而它抄的 Gemini probes 用的是**中间层**,
且**没有消融这个偏离**。这是一个现成的对照实验。

### 1.4 数据

**数据才是主力。** SafeWatch 2M 用 **TracIn**(梯度内积影响函数)筛到
**48K(2.4%)**,两条准则:对同类验证集平均影响为正、对全体验证集非负;
CoT 轨迹由 **Qwen3.5-27B** 生成。

⚠️ **消融里最大的单项增益来自这步数据筛选:+3.8% 平均准确率** ——
大于任何架构选择。它卖的是级联架构,抬分的是数据。这一点值得在我们的
消融设计里记住:架构对照必须固定数据,否则测的是数据不是架构。

### 2.1 ★ Stop Early, Spend Less（2606.10487）—— 最近的邻居

**做的事**：在 LLM **生成过程中**逐 token 跑冻结隐状态上的轻量探针，
越过阈值就提前终止，避免用户先看到不安全内容。

| 维度 | 它 | 本工作 |
| --- | --- | --- |
| 模态 | **文本**（LLM 自己的输出流） | **视频**（外来输入流） |
| 探针 | 双头（MLP+线性凸组合 α=0.8），层 21 | 冻结 SigLIP2 + 多通道融合 |
| 聚合 | topK pooling (K=16)，默认 max 聚合 | CUSUM（有重置、有延迟界） |
| 采样 | 每 π 步探一次（π=2 减半开销） | 随机化调度 + 突发回溯 |
| 保证 | **无**。自陈"thresholds tuned on a fixed validation set per dataset; deployment should re-calibrate per task" | conformal + ACI + anytime |
| 成绩 | F1 0.795（vs 完整 guard 0.85）；+0.1ms vs 450–600ms | — |

**为什么它同时是竞争和佐证**：
- 竞争：`流式 + 廉价探针 + 提前触发` 这个组合已经有人做了，不能当卖点。
- 佐证：它和 SafeLens 的 Limitations **说的是同一句话** ——
  阈值要按部署场景重调，没人给保证。两篇独立工作在同一个口子上停下，
  说明这个口子是真的，不是我们编出来的。

⚠️ 但要注意它的设定差异:**它审的是模型自己的输出**,所以
"提前终止"是可行动作;我们审的是**外来输入流**,拦不住上游,
只能标记/升级 —— Kotte Prop 8 的 emit-only 障碍在我们这边更紧。

## 3. 还没被做的

SafeLens 明确**没有**做的四件事，正好是提案里最有分量的部分:

### 3.1 流式与时序定位（最大空档）

SafeLens 是**整条视频分类**，≤1fps，无增量判决、无 ν、无检测延迟。
`E[(τ−ν)⁺]` 这套形式化它完全没碰。

⚠️ 但 QCD 已被用在 hallucination onset 上（2606.12476），
所以"把 QCD 用于 AI 安全"本身不新，新的只能是**视频流 + 受控观测预算**
这个组合，以及对抗自适应对手的随机化调度。

### 3.2 校准与保证 —— 而且这是 SafeLens 自己点名的局限

> SafeLens 的局限（其附录 A）：**"cascading threshold requires
> validation-set tuning across different deployment contexts"**

**这正是 conformal 校准要解决的问题。** 他们手调阈值，我们给
distribution-free 的下界 + ACI 跟踪漂移。这是最干净的差异化切入点。

⚠️ 前提是 2606.29054 的不可能性结果不会把这条堵死。**先读那篇。**

### 3.3 政策归纳与 out-of-policy

没有查到有人做"从标签反推政策定义"或"内容有害但无条款覆盖"的第四动作。
这块看起来是空的。

### 3.4 ★ 流式系统约束 —— 这是贡献，不是附录

⚠️ **早先版本把这节写成「分量不够，更适合作为支撑材料」，判据是
「这些是工程」。这个判据错了。** 驱逐、截止期、跨流 batching、采样率
不是「同一个问题的工程实现」，是**只有流式设定才存在的约束** ——
在 SafeLens 的整条视频分类里它们不是被解决了，是不会出现：

| | 整条视频分类（SafeLens） | 流式（本工作） |
| --- | --- | --- |
| 输入长度 | 有界、已知 | 无界 → **必须驱逐**，没有"全看"这个选项 |
| 截止期 | 无（离线批处理） | 下一帧到达前必须出结果 → 算不完就积压，**积压计入 E[(τ−ν)⁺]** |
| batching | 视频之间天然成批 | 单条流一次一帧 → **必须跨流拼 batch**（实测 4.4 → 46 fps） |
| 采样率 | 精度/成本权衡 | **召回硬天花板**：1 秒 needle @0.5fps 期望只覆盖 50% |

最后一行是关键区别：离线设定里降采样是省钱，流式里降采样是
**丢掉永远拿不回来的正例**。这不是调参，是可行域边界。

#### 3.4.1 从 SafeLens 自报运行时反推出的升级率

原文报了三个数：整体 ~1.76s、S1 单独 ~0.04s、S2 单独 ~5.02s。于是

```
1.76 = 0.04 + r x 5.02   ->   r = 34.3%
```

**他们的升级率是 34.3%。这个数原文没写，是从它自己的运行时反推的。**

它同时解释两件事：

1. **在他们的设定里合理** —— 基线是"全部走 S2"= 5.02s，1.76s 是 2.85x 加速。
2. **在我们的设定里是灾难** —— 我们实测成本交叉点 r\* = 2.53%（真实分辨率）。
   34.3% 远在其上：按我们的成本模型，这个级联**比统一用中间层还贵**。

而且 34.3% 与 Kotte Prop 3 完全自洽：其 acc=76.7% → µ≈0.23，
α=0.05 时下界 (0.23−0.05)/0.95 = 19.3%，34.3% 在其上。
**他们的升级率不是调出来的，是被基础风险顶上去的。**

#### 3.4.2 SafeLens 的哪些设计在流式下直接失效

> ⚠️ 早先版本这张表有两处错,已更正(详见 §1.1 的更正说明)。
> 尤其:**不是"探针不能流式"** —— 探针的 `max_t v̄_t` 恰恰是在线可算的
> (§1.3)。不可迁移的是**他们的用法**,不是那个机制。

| 设计 | 为什么它的**用法**不迁移 |
| --- | --- |
| `max_t v̄_t` 取自一次**全视频前向**(Alg.2 第 4 行) | 机制是因果的,用法不是:他们等 T 帧全部编码完再回头取 max。改成逐 tick 更新即可流式 —— 但那样就要面对延迟、重置、阈值漂移,而这些他们都没有 |
| 升级后才生成 caption,但要 **T 次** Florence-2 | 离线 T 有界;**流式下 T 无界**,S2 开销不收敛 |
| S2 = **全视频前向 x2** + T caption + CoT = 5.02s | 超过任何流式截止期;且第 12 行要重看整条视频,流式下那条视频还没结束 |

实测对照（`sg2/realtime.py` 的 `TierLoad`）：

| sentinel fps | 截止期 | SafeLens 整体 1.76s | S2 单独 5.02s |
| --- | --- | --- | --- |
| 0.5 | 2.0s | 1.1x 余量 ✓ | ✗ |
| 1.0 | 1.0s | **0.6x 算不过来** | ✗ |
| 2.0 | 0.5s | **0.3x 算不过来** | ✗ |

**即使升级率降到 0，光整体 1.76s 在 ≥1fps 就已经排不开。**
SafeLens 不能靠"反复调用"变成流式 —— 这不是实现问题，
是 34.3% x 5.02s 的结构决定的。

#### 3.4.3 由此得到的真正新结论：升级率被三面夹

```
     µ − α                              /        D − T1  \
  ───────────   ≤   r   ≤   min ( r* , ──────────────── )
     M − α                              \          T2    /
  认证下界(Kotte)          成本上界        实时上界(队列稳定)
```

**第三项是流式独有的** —— SafeLens 的设定里 D = ∞，这一项不存在。
而这个可行域**可以是空的**，且闭式就能判，不用跑实验。

这比"我们也做了级联"有分量得多：它是一个**不可能性结论**，
而且它的三条边分别来自三篇不同的线索（Kotte 的下界、我们的成本模型、
排队稳定性），单独任何一条都推不出来。

## 4. 定位建议

**不能再说的**：
- "第一个级联式视频 guardrail"
- "廉价层 + 升级" 本身
- ★ "第一个把廉价探针用于流式审核" —— 2606.10487 已做（文本模态）
- ★ "探针不能做流式" —— **错的**。rolling 统计量本来就是在线可算的（§1.3）

**可以说的**：
1. ★ **流式是不同的问题，不是不同的部署方式**：无界输入强制驱逐、
   截止期强制跨流 batching、采样率直接封顶召回。SafeLens 的三个核心
   设计（全帧 rolling probe / 逐帧 Florence-2 / 5.02s CoT）**没有一个
   能迁移**，见 §3.4.2
2. ★ **升级率三面夹的不可能性结论**（§3.4.3）—— 实时上界是流式独有的
3. **冻结基座**：SafeLens 微调 2B，我们不动基座 → 换代免费变强可测
4. **有保证**：SafeLens 手调阈值并自陈为局限，我们给校准下界
5. **政策可变**：归纳、out-of-policy、零日 —— 目前无人涉足

**最诚实的一句话定位**：

> 在 SafeLens 已证明"级联对视频审核有效"之后，本工作问的是：
> 当基座冻结、政策会变、且必须逐帧实时判定时，**什么还能被保证**。
>
> 而"必须逐帧实时判定"这个前提不是加一个约束，是换了一个问题：
> SafeLens 34.3% 的升级率（§3.4.1，从其运行时反推）在任何流式截止期下
> 都不可行，且这与它做得好不好无关。

## 6. ★ 2606.29054 读完了：不是威胁，是礼物

Kotte 2026, *When Can Conformal Risk Control Certify LLM Outputs?*
三个结果全部改进了我们的设计。

### 6.1 它给了升级率的**闭式下界**

> **Proposition 3（Sharpened two-sided abstention floor）**
> 任何 distribution-free 方法必须弃权的比例
> ≥ (µ − α) / (M − α)，其中 µ = 基础风险，M = ess sup R。

**在级联里「弃权」就是「升级」。** 所以这直接是**升级率的下界**：

| 廉价层漏报率 µ | 必须升级 ≥ |
| --- | --- |
| 2% | 0.0% |
| 5% | 0.0% |
| 10% | **5.3%** |
| 20% | 15.8% |
| 40% | 36.8% |

原文实测 NER/QA/CLS 上审计出的 M 恰好 = 1.0（每个格子里都有完全漏掉的
样本），所以通常用保守形式 (µ−α)/(1−α)。我们的漏报损失是 0/1，同样 M=1。

### 6.2 由此得到一个**可闭式计算的张力**

两个约束从两头夹住升级率：

```
下界 = (µ − α)/(1 − α)     要有保证,至少升这么多
上界 = r*(成本交叉点)       要比基线便宜,至多升这么多
```

代入我们实测的 r* = 2.53%（real 分辨率）：

| µ | 下界 | 上界 | 结论 |
| --- | --- | --- | --- |
| 5% | 0.0% | 2.5% | 可同时认证且更便宜 |
| 7% | 2.1% | 2.5% | 勉强 |
| **10%** | **5.3%** | 2.5% | **不可兼得** |
| 30% | 26.3% | 2.5% | 不可兼得 |

> **廉价层漏报率超过约 7%，「有保证」和「比基线便宜」就不可兼得。**
> 而且这不用跑任何实验，闭式算得出。

这是**我们的角度而非原文的**——它不做级联也不谈成本。
把它的下界接到我们的成本模型上，得到一个新的、可证的结论。

### 6.3 它点名 ACI 失败，但**恰好证明了我们审计设计的必要性**

> **Proposition 8（Emit-only feedback obstruction）**
> 只在被放行的样本上观测风险时，任意保证 anytime emitted-risk 的方法
> 都能被构造出违反。**ACI 正是 emit-only**，所以它的失败是反馈模型的
> 性质，不是步长 γ 调不好。正面保证需要 **full feedback —— 验证器，
> 或被弃权样本上的标签**。

「被弃权样本上的标签」在我们的系统里**就是随机审计采样**（`docs/04` §4.4）。
我在第 3 轮就自己推出过这个必要性（「审核员只看被标出来的，漏报按定义
不进队列」），这篇把它形式化了。

> **所以审计不是可选优化，它是保证成立的前提。**
> 而 `docs/06` 已经把审计成本作为一条显式成本线入账了。

### 6.4 ACI 的适用边界（原文 §3.5 实测）

| 漂移类型 | 静态 CRC 违反 | ACI 违反 | ACI 有效? |
| --- | --- | --- | --- |
| 时序漂移 | 60% | **4%** | ✅ |
| 逐渐劣化 | 56% | **12%** | ✅ |
| **跨数据集** | 88% | **88%** | ❌ |

**正好对应我们的两个场景：**

- **流内漂移** → 时序漂移 → **ACI 可用** ✓
- **零日政策 / 换 benchmark** → 跨数据集 → **ACI 不可用**

但原文说清了原因：跨数据集那组 µ = 0.40–0.84 ≫ α = 0.10，
**本来就在不可行区间**。「调参救不了不可行」。合规的那几次弃权 75–100%。

所以正确做法不是换个 γ，而是**先查可行性**。

### 6.5 三步部署配方（直接采纳）

1. **可行性**：算 µ；若 µ > α，任何有效方法弃权 ≥ (µ−α)/(M−α)
2. **界与分数**：严格目标下用 Bernstein 或 e-CRC；稀缺时用 e-CRC
3. **漂移**：在目标域**重查可行性**；可行区间内部署 ACI（γ=0.01）；
   有 full feedback 时用 §3.6 的 anytime-valid monitor

⚠️ 第 2 步我们目前用的是**精确二项（Clopper-Pearson）**。
原文的层级是 Hoeffding ⊆ Bernstein ⊆ e-CRC，没有列精确二项。
**待办**：把精确二项放进这个层级里对比，确认它在 n≈45 的稀缺区间是否
优于 e-CRC。
