# 10 · 政策归纳：从标签反推政策定义

**问题。** 到一个新 benchmark 时，手里有的是**标签，不是政策文档**——
标签里编码着一条从没被写下来的政策。`docs/06 §3.6` 的零日实验原本假设
"有人把政策写出来"，这在换 benchmark 时不成立。

**做法。** 用少量带标样本反推出政策定义文本，再走既有的少样本适配与校准。
整条链不动一次梯度。

## 1. 它属于哪一级：都不属于

三级都是**在线**组件，有延迟预算。政策归纳每个新 benchmark 只跑一次、
要一次看很多样本、要迭代、没有延迟约束——它是**离线编译器**，不是推理层。

「哪一级」和「用哪个模型」是两个问题：

| 角色 | 谁做 | 为什么 |
| --- | --- | --- |
| 提议 / 修订 | frontier，离线 | 写定义需要强推理；次数少，贵得起 |
| 评估候选 | **中间层** | 要跑很多次，必须便宜 |
| 在线消费 | 中间层 | 只**读**政策，自己从不生成 |

不让中间层生成的三个理由：4B/8B 写定义质量不如 frontier；会把在线路径
耦合上一个生成步；中间层是在**我们的**政策格式上 LoRA 过的，让它发明格式
属于离分布。

不让在线 analyst 生成的理由：单个事件就改政策，正是
`PolicyGapTracker.MIN_CASES = 5` already 挡住的那个错误。归纳需要一批样本。

## 2. 必须是循环

单轮提议**看不见自己的错误**。加上循环，它才从"让 LLM 写条政策"变成
有可测目标的优化：

```
P ← propose(正例, 负例)                 # frontier
repeat:
    preds  ← 中间层(dev 集, policy=P)    # 便宜的那一级来评
    fp, fn ← 与标签不符的两类样本
    P      ← revise(P, fp, fn)          # frontier 看自己的失败
until F1 不再上升 or 预算用尽
return dev 上最好的那一轮                # 不是最后一轮
```

这与 `docs/08 §4.3` 的离线 prompt 编译是**同一套机械**，只是优化的文本
换成了政策定义——`pool="compile"` 本来就是为它留的。

实测（玩具样本，judge 按条款关键词匹配）：

| 轮 | 条款 | F1 |
| --- | --- | --- |
| 0 | 禁止出现厨房场景。 | 0.000 |
| 1 | 禁止画面中出现刀具。 | 1.000 |

第 1 轮之所以能修对，是因为它看到了第 0 轮的具体错误：
误报「厨房在做饭」「厨房的砧板」，漏报「拿着一把刀」「刀架上有刀」。

## 3. 三套数据，一个都不能混

| 集合 | pool | 作用 |
| --- | --- | --- |
| propose | `exemplar` | 展示给生成器 |
| dev | `compile` | 给候选打分、选最优轮 |
| eval | `eval` | 最终报数，**归纳全程不得接触** |

⚠️ 在 eval 上调政策，报出来的 F1 没有意义。`induce_policy()` 会显式拒绝
propose 与 dev 重叠；`sg2.schema.load()` 的池守卫让跨池使用不可能被意外
违反。这是那个设计决定在这里的兑现。

## 4. 与既有机制的接口

| 既有机制 | 如何衔接 |
| --- | --- |
| `uncovered` / `PolicyGapTracker` | 同一个生成器，只是种子不同：归纳由**带标数据**驱动，补缺由线上**累积的 uncovered**驱动 |
| `approve(reviewer=...)` | 归纳产物是 **draft**，不得自动生效 |
| `swap_policy()` | 新政策 → 新指纹 → **校准纪元边界** |
| 45 正例的 conformal 下界 | 归纳**之后**才谈校准；归纳用的样本不能再当校准集 |

## 5. 这构成什么实验

四条对照，同一个新 benchmark：

| 设置 | 预期 | 说明 |
| --- | --- | --- |
| 用**我们的**政策零样本 | 差 | 政策定义不一样，这是起点 |
| 用 benchmark **自带**的政策文本 | 好 | 上界（若它有政策文档） |
| **从 k 条标签归纳**（本方法） | ? | k ∈ {5, 10, 20, 50} |
| 在同样 k 条标签上微调 | ? | 要打败的对象 |

主张：**k=20 时归纳政策 ≈ 微调，但零梯度、产物可读、且能挂 conformal 保证。**

这比原来的零日实验强：原来是"人工编辑语料"，现在是"从 k 条标签自动归纳"，
自动且可测。

### 三个必须报告的风险

1. **过拟合到表面特征。** k=20 时生成器可能写出"禁止出现红色区域"——
   如果正例恰好都偏红。dev 集能抓一部分，但**归纳出的政策文本必须原样
   写进论文**：它是人可读的，这本身就是可解释适配的卖点，也让审稿人能
   自己判断有没有作弊。
2. **循环可能没有增益。** `InductionResult.improved` 显式报告最优轮是不是
   第 0 轮。如果多数情况下单轮就够，就该老实说循环是多余的。
3. **judge 的选择会影响结论。** 用中间层评估时，中间层自身的能力上限会
   限制可归纳出的政策复杂度——`docs/01 §4.2` 实测 2B 读不懂政策，
   拿 2B 当 judge 会让任何政策都得零分。**judge 至少要用 4B。**
