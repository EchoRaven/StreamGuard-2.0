# 11 · 政策生成如何接进训练

`docs/10` 讲了怎么从标签归纳出政策。本文讲**归纳出来的政策怎么真的起作用**。

## 1. 核心风险：SFT 会教模型「背政策」

适配链的关键一步是：**中间层不重训，只是读新政策**。

```
新 benchmark(只有标签)
  → induce_policy(k 条标签)        [离线,frontier 生成 + 中间层评分]
  → draft 条款 → 人工 approve
  → 政策语料更新 → 新指纹 → KV 缓存失效 → 校准纪元边界
  → 中间层**不重训**,读新政策
  → 45 正例重校准 → conformal 保证恢复
```

这一步只有在模型**真的读政策**时才成立。而在固定语料上 SFT，模型完全
可以记住「C1 就是色情」，从此不再读条款文本——那么生成的新政策不会
改变它的判决，`docs/10` 整条链白做。

**这不是理论担忧，而是 SFT 的默认结果。** 训练数据里若「同一种画面
总是配同一条政策、总是同一个答案」，最省力的解就是记住画面→答案的映射，
政策文本变成装饰。

## 2. 判据：反事实翻转

**同一段视频，给两条不同的政策（一条覆盖、一条不覆盖），判决应当翻转。**
不翻转 = 模型在忽略政策。

`sg2/eval/sensitivity.py` 把它做成可测量：

| 指标 | 含义 |
| --- | --- |
| `flip_rate` | 判决随政策改变的比例 |
| `correct_rate` | 不仅翻转，且方向正确（覆盖时 flag、不覆盖时不 flag） |
| `always_flag` | 两种政策都 flag——典型的「背下来了」 |

⚠️ 对照的两条政策必须**条款数相同且都带安全出口**。否则差异可能来自
条款数，或来自「无处可去」——实测只有禁止性条款时，模型会被迫用
`uncovered` 表达「不违规」（见 `docs/10 §6`）。

### 实测基线（SFT 前）

8 个测试图样本，Qwen3-VL：

| 模型 | 翻转率 | 方向正确率 | 判定 |
| --- | --- | --- | --- |
| 2B | 1.00 | 1.00 | ✓ 读政策 |
| 4B | 1.00 | 1.00 | ✓ 读政策 |
| 8B-nf4 | 1.00 | 1.00 | ✓ 读政策 |

**底座模型确实在读政策。** 所以这是一条**可被 SFT 破坏**的既有性质，
不是需要从头训出来的能力。它必须是训练中**被监控的指标**，
而不是训练结束才测一次的评测项。

## 3. 防御：六种政策增强

`sg2/train/policy_aug.py`。每一种针对一条可被记住的线索：

| 增强 | 堵住的记忆线索 |
| --- | --- |
| `shuffle` | 条款位置 |
| `rename_ids` | 条款 id 与类别的固定对应 |
| `subset` | 「语料里总是这六条」 |
| `paraphrase` | 条款的固定措辞 |
| `inject_novel` | 「没见过的 id 一定不重要」 |
| **`mismatch`** | **内容与政策的固定对应** |

### mismatch 是最重要的一条

有一定比例（默认 25%）的样本，政策**不覆盖**画面里的内容，正确动作是
`clear`。做法是把目标条款从语料里**移除**，于是同一段视频配上不同政策，
正确答案不同。

**这是唯一能教会模型「答案由政策决定」的信号。** 没有它，模型学到的是
「看见这种画面就 flag」。

它同时补上了 `docs/08 §2.1` 窗口配比缺的第五类——实测 2B/4B/8B 四个
配置 `uncovered` 使用率全部 0/8，说明这个动作靠 zero-shot 学不会。

### 增强生效的自检

`mismatch_stats()` 报四个量，其中最要紧的是 **`unique_id_ratio`**：
接近 1 才说明 id 确实被随机化了，否则模型仍能把 id 与类别绑死，
增强形同虚设。

实测 100 条样本：`unique_id_ratio=1.0`，条款数在 4–8 间变动，
安全出口全保留。

## 4. 训练时怎么用

```python
from sg2.train.policy_aug import augment, AugConfig

for window in windows:                      # docs/08 §2.1 的因果窗口
    aug = augment(corpus, window.target_clause_id, cfg=AugConfig())
    yield {
        "policy": aug.corpus.render(shuffle_seed=None),   # 已 shuffle 过
        "target": {"action": aug.expected_action,
                   "policy_citation": aug.target_clause_id},
        "video": window.clip_id,
    }
```

⚠️ 目标里的 `policy_citation` 必须用**增强后的 id**（`aug.target_clause_id`），
不是原 id。用原 id 会让标签指向一个语料里不存在的条款，
而这在 loss 上看不出来。

## 5. 评测协议

| 阶段 | 必测 | 通过线 |
| --- | --- | --- |
| SFT 前 | 政策敏感度 | 记录基线（实测 1.00） |
| SFT 每个 checkpoint | 政策敏感度 | 不得显著低于基线 |
| SFT 后 | 在**训练时未见过的**生成政策上测 | `correct_rate` 不崩 |
| 归纳适配后 | 新 benchmark 上的 F1 | 见 `docs/10 §5` 四条对照 |

**否定条件**：若 SFT 后政策敏感度显著下降，则 `docs/10` 的政策归纳链
在本系统上不成立——应当直说，并考虑改为「每换一个 benchmark 就重训」
的方案（那会牺牲 training-free 这个卖点，但诚实）。
