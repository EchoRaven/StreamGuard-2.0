# 14 · 帧驱逐

**一个常见误解:以为这需要「哪一帧重要」的人工标注。不需要。**

驱逐是**压缩**问题不是分类问题。要问的是「丢掉这帧会不会改变判决」,
而答案**由模型自己给出** —— 用它自身的输出当目标,不用 ground truth。

真正难的是别的:**在线决策时不知道未来。** t 时刻要决定留不留某帧,
而它有没有用取决于 t+k 发生什么。这是延迟反馈下的预测问题。

## 1. 两种驱逐,可逆性不同

| | 可逆? | 策略 |
| --- | --- | --- |
| **KV 驱逐**(S3 视觉窗) | **可逆** —— 帧还在 ring buffer,可重新 ingest | 可激进、可学 |
| **Ring buffer 驱逐** | **不可逆** —— 滚出去就是硬 miss | 必须保守,只按时长/字节 |

这个区分是有用的:**ring buffer 让 KV 驱逐变成可恢复的**,
所以真正需要谨慎的只有 ring buffer 那一层。

## 2. 监督信号从哪来:自监督

`leave_one_out_importance()` 丢掉每一帧、看判决变不变。
**这就是「标注」,但它来自模型自己,不需要人看任何一帧。**

代价是 N+1 次前向,所以它是**离线**方法。在线用途是**事后回标**:
离线重放整条流、掌握全部未来后算出真值重要性,拿来训在线策略
(`hindsight_targets()`)。全程零人工标注。

## 3. ★ 实测:真实数据推翻了合成例子的结论

### 合成例子(单帧 needle)

| 预算 | fifo | stride | coverage | salience | hybrid |
| --- | --- | --- | --- | --- | --- |
| 3 | ✗ | ✗ | ✓ | ✓ | ✓ |
| 5 | ✗ | ✗ | ✓ | ✓ | ✓ |
| 8 | ✗ | ✗ | ✓ | ✓ | ✓ |

看起来 FIFO 完全不可用。

### 真实数据(25 条 SafeWatch unsafe 视频,24 帧→保 6 帧)

| 策略 | 判决一致率 |
| --- | --- |
| coverage | **92.0%** |
| stride / salience / hybrid | 88.0% |
| fifo | **80.0%** |

**差距小得多。** 更关键的是:

> **重要性集中度中位 = 0.000**

意思是**丢掉任何单独一帧都不改变判决** —— 真实 unsafe 视频里违规内容
通常**跨多帧持续存在**,不是合成例子里那种单点 needle。

### 结论要改

- 合成例子里 FIFO 惨败,是因为我**人为造了单帧 needle**
- 真实数据上 coverage 领先 FIFO **12 个百分点**,是真差距但不是致命
- **留一消融在真实数据上测不出重要性**(没有单点关键帧),
  所以事后回标这条路在 SafeWatch 这类数据上**收效有限**

⚠️ 这条修正本身是个教训:**合成例子里的结构(单帧 needle)是我放进去的,
不是数据里本来有的。** 拿它得出的强结论必须在真实数据上复核。

## 4. 实现

`StreamContext.append_frame(tokens, t_s, importance=None)`:

- `importance` 给定时按重要性驱逐,否则**安全退回 FIFO**
- **最新帧永不驱逐** —— 它正是当前要判的那帧
- **时间窗驱逐与重要性无关** —— 超窗的帧本来就该走

重要性可来自压缩域(关键帧、运动能量,**免费**)或 sentinel 分数,
都不需要人工标注。

## 5. 什么时候值得做

`ImportanceResult.concentrated` 先看这个数:

| 集中度 | 含义 |
| --- | --- |
| 接近 1 | 少数帧决定判决 → 驱逐策略很重要 |
| 接近 0 | **丢哪帧都一样 → 再优化也没收益** |

真实 SafeWatch 数据上是 0.000,所以**在这类数据上优化驱逐策略的收益有限**。
收益大的场景是短 needle(合成数据、对抗样本),那正是 `docs/02` 的
时序稀疏度轴要控制的变量。
