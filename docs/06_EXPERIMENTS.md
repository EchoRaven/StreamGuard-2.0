# 06 · 实验协议

每个实验都写死**否定条件**。没有否定条件的实验不是实验，是演示。

## 1. 预实验（天级，先于一切）

这三件事全部是天级而非周级，**任何一件都能提前否掉前提**。在投两周做 MVP
之前先做完。

### 实验 1 · 成本交叉点（半天，纯算术）

算 1.0 本地 2fps 与（0.2fps sentinel + r% 升级到 frontier）的 $/stream-hour，
把 r 当自由变量，解出 2.0 能赢的 r 上界。

```
C_1.0   = GPU摊销 × 2fps解码编码时间
C_2.0(r) = C_sentinel + r × (C_midtier + q × C_frontier) + ε × C_audit
```

别忘 `ε × C_audit` —— 随机审计是保证的价格，必须显式入账。

**否定条件**：实验 2 测出的 r 远超本实验解出的上界 → Pareto 曲线会输在
$/stream-hour，而且输给自己的 1.0。这是最大的隐性风险。

#### ★ 已跑（2026-09-19），结果是个警告

用本机实测延迟（2B 1.23s / 4B 0.37s / 8B-nf4 0.59s）跑 `scripts/cost_model.py`：

| 基线 | 均匀成本 | **交叉点 r\*** |
| --- | --- | --- |
| 均匀 2fps 跑 **2B** | $0.861/stream-hour | **5.61%** |
| 均匀 2fps 跑 **4B** | $0.259/stream-hour | **0.07%** |

**基线越强，自适应的空间越小。** 4B 又快又准（`docs/01 §4.2`：延迟
0.37s、policy-following 8/8），均匀跑它只要 $0.259/h——留给自适应的
预算几乎为零，升级率必须低于 **0.07%** 才划算。

这不是说方案不成立，而是说**论文必须把基线选择讲清楚**：
对着一个慢基线（2B）画 Pareto 图会显得很好看，但那是基线弱不是方法强。
诚实的做法是**用最强的可行基线**（4B），并接受结论可能是
「在算力充裕时自适应分配的收益有限，价值在算力受限或流数极多时」。

#### 审计是最敏感的一项

审计成本直接决定前提成不成立：

| 抽查强度 | 审计成本 | r\*（2B 基线） | r\*（4B 基线） |
| --- | --- | --- | --- |
| 0 片段/h | $0.00 | 7.91% | 2.37% |
| 0.5 片段/h | $0.25 | 5.61% | 0.07% |
| 2 片段/h | $1.00 | **−1.30%** | **−6.84%** |

**每流每小时抽查 2 个片段，前提就直接不成立了。** 而 ACI 的无偏漏报
信号恰恰依赖审计——所以「保证」和「成本优势」之间有真实的张力，
这一点必须在论文里明写，不能只说保证便宜。

⚠️ **单位陷阱。** 初版把审计率写成「每个 sentinel tick 的比例」，
1% × 1800 tick = 18 次人工 = **$9.00/stream-hour**，是均匀基线的十倍，
于是"任何升级率都赢不了"。但 1 小时视频请人看 18 次没有道理——
审计的单位是**片段**不是 tick。这个单位错误会让前提看起来完全不成立。

### 实验 2 · A/B/C 分层（1–2 天，零标注）

有 needle 的 ground-truth 时间戳，把廉价模型和 frontier 都喂**那一帧**
（精确帧，不抽样），看 2×2：

| 廉价 | frontier | 分层 | 含义 |
|---|---|---|---|
| ✓ | ✓ | A | 覆盖率决定一切，廉价层碾压 |
| ✗ | ✓ | B | **真正的问题区** |
| ✗ | ✗ | C | 不在这一帧里，需时序/语音通道 |

写入 `measurements/abc.<cheap>__<frontier>.<date>.jsonl`（**是测量不是标签**，
见 SPEC.md §4）。本机可跑：廉价模型用 Qwen3-VL-2B 或 SigLIP2 线性探针。

**否定条件**：B 占比高**且**在目标召回处 r 不可接受 → 级联在这个数据分布上
不成立。C 占比高 → 逐帧检测范式对那部分内容本身就是错的，再强的 backbone 也没用。

### 实验 3 · 阈值稳定性曲线（1 天）

对每个类别，把校准正例数 n 从 10 扫到全量，画 τ̂ 及其置信区间随 n 收窄的曲线。

一张图回答三个审稿人问题：新政策要多少标注、区间多宽算可用、哪些类别天生难校准。

**交叉验证**：收不拢的类别应与实验 2 的 B 层**高度重合**。两者不重合，
说明有一个测错了。

## 2. B 类三分诊（仅当实验 2 显示 B 占比高）

"B 类识别不出来"混了三种病因，修法完全不同。大多数人嘴里的"B 类太难"
其实是第 1 或第 2 种，却被当成第 3 种。

| # | 诊断 | 病因 | 修法 |
|---|---|---|---|
| 1 | 给廉价模型**全分辨率原帧**，成了 | 分辨率 | 分辨率分级 + crop proposal |
| 2 | 全分辨率不成，用 B 层样本**蒸馏后**成了 | 容量/训练 | 蒸馏 sentinel（训练集=自动分出的 B 层） |
| 3 | 两者都不成 | 真能力上限 | 上下文先验 + 保底覆盖 ρ |

## 3. 核心实验

### 3.1 自适应 vs 均匀（头图）

**同 backbone、同平均预算**，两条 Pareto 曲线。这是全文唯一干净可证伪的主张。

⚠️ 基线必须**也是曲线**（1.0 扫 fps 与分辨率），否则"2.0 是曲线、1.0 是点"
的对比会被判定为不公平。

**否定条件**：同预算下自适应不优于均匀 → 论题不成立。

### 3.2 逐分层 ROC

按 A/B/C 分别画，在每层的目标召回处读出 r。

⚠️ **不要看聚合 AUC** —— 它会被占绝大多数的 A 类抬得很好看，把 B 类的问题
完全盖住。第 11 轮的教训：逐项性质不能用全局指标去测。

### 3.3 优雅退化验证

人为把 sentinel 在某类别上致盲（随机化其分数），验证召回确实落到
`uniform(ρB)` 的下界**而不穿透**。

**否定条件**：穿透下界 → 保底覆盖的实现有 bug，或 ρ 没有真正旁路。

### 3.4 少样本边界适配

每类别 n ∈ {1, 5, 10, 30, 100, 全量}，机制 A/B/C 三条 AUC 曲线同图。

**期望**：A 在 n<5 领先，B 在 5–30 领先，C 在 n>50 反超。
**否定条件**：三条线在所有 n 上都平 → 少样本适配没有价值，`03_ADAPTATION.md`
的大半失去意义。

⚠️ 样例来源必须与 eval 集**不同源视频**，否则测的是记忆不是泛化。

### 3.4b 中间层规模对照（4B vs 8B）

同一 harness，中间层换规模，量三件事：

| 量 | 说明 |
| --- | --- |
| 协议遵守 | 格式合法率、引用准确率、`uncovered` 使用率 |
| **judge 能力** | 当政策评估器用时的 P/R/F1（`scripts/judge_bench.py`） |
| 资源 | 显存峰值、延迟、加载时间 |

前两项都**不需要真实安全数据**——用 lavfi 造真值已知的判定任务即可，
测的是"能否按给定政策做二分类"，正是 judge 在归纳循环里要干的事。

⚠️ **F1 单独看会骗人。** 正负各半时，一个恒定输出的模型也能拿到不难看的
F1。必须同时报告**常数基线**（全 flag 的 F1）与**动作多样性**
（只输出一种动作 = 没在判定，只是在复读）。`judge_bench.py` 两项都报。

**否定条件**：若 4B 与 8B 在三项上都无显著差异 → 规模不是这一层的瓶颈，
论文里应直说，并把中间层固定在 4B 以省算力。

### 3.5 换 backbone 纵向研究

同一 harness，backbone 换代。量化"免费变强"与各家拒绝率差异。
**成本极低，且没人给 guardrail 做过。** 副产物：同一数据集上 A/B/C 比例
随模型代际的迁移曲线。

### 3.6a 政策归纳（换 benchmark）

到一个政策定义不同的新 benchmark，从 k 条标签归纳政策定义，
对照"用我们的政策零样本 / 用它自带的政策 / 在同样 k 条上微调"。
k ∈ {5, 10, 20, 50}。详见 `docs/10_POLICY_INDUCTION.md` §5。

**否定条件**：归纳政策在任何 k 上都打不过"用我们的政策零样本" →
归纳没有产生信息，整条线不成立。

⚠️ judge 至少用 4B。实测 2B 读不懂政策，拿它评估会让任何候选都得零分。

### 3.6 零日政策

`zeroday_holdout` 的 2 个类别，只改政策语料 + 45 个正例重校准。
报告**标注量 vs 重训成本**的对比 —— 这是相对 1.0 最硬的差异化点。

### 3.7 消融

- describe-then-judge vs 直接判断（§5 的有损瓶颈，**必做**）
- 各信号通道的边际贡献：压缩域 / ASR / OCR / 弹幕逐一移除
- 随机化调度 vs 确定性调度（对抗部分的实证）

## 4. 对抗

| 攻击 | 做法 | 防御 |
|---|---|---|
| Needle placement | 按采样表定时投放 | 随机化采样调度（§3 理论的实证） |
| **Cost amplification** | 注入运动噪声使去重失效、token 爆炸 | 运行时硬上限（`05_RUNTIME.md` §3） |
| 盲区定向 | 专挑 sentinel 无判别力的 B 类 | ρ 的 minimax 保证 |
| 元数据伪装 | `camouflage` 条件 | 强制视觉通道 |

cost-amplification 是对 guardrail 的一种 DoS，**基本没人做过**，值得单列。

## 5. 报告纪律

1. 所有结果带成本核算（API token + 解码帧数 + **审计预算**）
2. 每个 backbone 的拒绝率作为发现报告，不隐藏；注明不可跨时复现
3. 校准状态随每个数字一起报：`calibrated(n=120)` / `estimated(n=12)`
4. 逐 cell 结果只报观测值，**不声称保证** —— 保证只在逐类别粒度上成立
5. 否定结果照常写。第 1 轮就定下的：带干净刻画的负面结果在这个领域有价值，
   因为现在所有人都默认级联能 work，没人给过条件。
